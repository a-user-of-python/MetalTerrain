Structures Guide

Seeded low-poly structures — houses, towers, trees, boulders, wells, windmills, dungeons — placed deterministically and drawn with one instanced draw call per kind.

The seven kinds

KindWhat it isGeometry
housePlaster hut with roof prism, chimney, doorBoxes + triangular prism
towerStone watchtower with crenellationsCylinders + boxes
treeTwo-tier coniferCylinder trunk + 2 cones
boulderDisplaced sphere rockIcosphere-ish, noise-displaced
wellStone well with posts and roofCylinder + boxes + prism
windmillTower mill with rotating-cap silhouetteCylinder + boxes (blades as quads)
dungeonDark entrance moundDisplaced half-buried structure

All meshes are original procedural geometry — boxes, prisms, cylinders, cones, displaced spheres — unit-ish in scale (a few world units tall, base at y = 0). MTStructureBuilder.mesh(for:) is deterministic: same kind → identical geometry, every time.

Placement policy

Placement lives in MTTerrainWorld, not in the mesh code:

  • 12 candidates per chunk from a chunk-seeded PRNG — the same chunk always proposes the same candidates.
  • A candidate is kept when the structure-density noise field (config.structureNoise, default seed 90210, 3 octaves, no warp) exceeds a threshold derived from config.structureDensity (default 0.35).
  • Kept candidates must sit on land: terrain height in [beachTop, 0.85] — no structures in the ocean, none on the highest peaks.
  • The kind comes from a second noise field mapped over the 7 kinds; rotation (radians about Y) and scale (uniform) come from the PRNG.
  • structuresEnabled == false → structures(in:) returns []. Toggling is live.
// Query placements yourself (e.g. for gameplay logic):
let placements: [MTStructurePlacement] =
    world.structures(in: MTChunkCoord(x: 3, z: -2))
for p in placements {
    print(p.kind, p.position, p.rotationY, p.scale)
}

// Tune density / toggle:
var config = MTTerrainConfig.default
config.structureDensity = 0.6   // more structures (0...1, clamped)
config.structuresEnabled = true
world.config = config
world.structuresEnabled = false // live alias — clears instances immediately

Rendering: one instanced draw per kind

The renderer queries world.structures(in:) for each visible chunk on the build queue, then fills per-kind instance buffers (model matrix + tint, 80-byte MTInstanceData). Each frame draws all houses in one instanced call, all trees in one, and so on — 7 draw calls total regardless of count.

  • Instance buffers are rebuilt only when the visible chunk set changes (or the enabled flag toggles) — no per-frame cost.
  • Placement queries run on the build queue; the buffer swap happens on the main queue.
  • Structures are double-sided (cull mode .none): generated low-poly triangles occasionally have inconsistent winding, and visible is better than "correct but missing".
  • Structures are skipped in reflection passes (mirror images are small; the cost isn't worth it).
  • Structures are not in the ray-tracing acceleration structures — only terrain chunks are traced.

Custom structures

The placement system is in the world module; the mesh system is open for extension:

// Build any kind's mesh for your own use (previews, editors):
let (vertices, indices) = MTStructureBuilder.mesh(for: .windmill)
// vertices: [MTSimpleVertex] (position/normal/color as SIMD3<Float>)
// indices: [UInt32]

// Convert to the terrain vertex format if you need to render it yourself:
let terrainVerts = vertices.map {
    MTVertex(position: $0.position, normal: $0.normal, color: $0.color)
}

Adding a brand-new kind means: a new MTStructureKind case, a builder function in MTStructures.swift, and a placement rule in the world module. The instanced renderer picks up new cases automatically via MTStructureKind.allCases.

Best practices

  • Don't fight the density field. If you want a village here, place it yourself as app-level content via the overlay closure — the seeded scatter is for ambient dressing, not quest locations.
  • Test toggle behavior. structuresEnabled = false must clear instances without rebuilding the world (it does — but verify in your UI flow).
  • Mind the scale. Structures are a few world units tall against 1000-unit chunks and a 400-unit height scale. They're set dressing, not architecture to walk through — unless you scale them up via custom placements.
