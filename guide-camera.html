Camera & Input

The library never moves the camera — that's your app's job, and it's where feel lives. This guide covers the integration contract, the standard camera rigs, and the pitfalls that put cameras inside mountains.

The contract

  • You call setCamera every frame (from onFrame or your own MTKViewDelegate). No call → the previous frame's camera persists; never called → black screen.
  • Signature (view): setCamera(position:target:fovDegrees:aspect:near:far:) with defaults fovDegrees = 55, near = 1, far = 4000. The renderer's version takes all six parameters (no defaults).
  • setCamera also drives streaming — the view calls renderer.update(cameraTarget:) internally with the target's XZ. With the raw renderer, you must call update(cameraTarget:) yourself every frame.
  • onFrame runs on the render thread. Safe: camera math, setCamera, reading renderer. Unsafe: touching UIKit/SwiftUI state — shuttle values through your coordinator on the main thread.
  • Always pass the real aspect. Float(view.bounds.width / max(1, view.bounds.height)), recomputed on rotation. A stale aspect stretches the world.

Orbit camera (third-person / map view)

struct OrbitCamera {
    var target = SIMD3<Float>(0, 100, 0)
    var yaw: Float = 0.8, pitch: Float = -0.45, distance: Float = 1400

    mutating func apply(to view: MTTerrainView) {
        // Clamp pitch so you can't go fully under the world:
        pitch = max(-1.45, min(-0.05, pitch))
        distance = max(50, min(6000, distance))
        let eye = SIMD3<Float>(
            target.x + distance * cos(pitch) * sin(yaw),
            target.y + distance * sin(pitch),
            target.z + distance * cos(pitch) * cos(yaw))
        let aspect = Float(view.bounds.width / max(1, view.bounds.height))
        view.setCamera(position: eye, target: target, aspect: aspect)
    }
}
// Input mapping: one-finger drag → yaw/pitch, pinch → distance,
// two-finger drag → pan target (clamped to ±8000 world units).

Walk camera (first-person)

The walk camera has one job the orbit camera doesn't: never go under the terrain. Sample the heightfield:

struct WalkCamera {
    var pos = SIMD2<Float>(0, 0)   // XZ position
    var yaw: Float = 0
    var pitch: Float = -0.08
    let eyeHeight: Float = 2      // player size

    mutating func apply(to view: MTTerrainView, world: MTTerrainWorld,
                        moveInput: SIMD2<Float>, dt: Float) {
        // Move on XZ; block water with axis slide (see Examples).
        let speed: Float = 45
        let forward = SIMD2<Float>(sin(yaw), cos(yaw))
        let right = SIMD2<Float>(-forward.y, forward.x)
        let delta = (forward * moveInput.y + right * moveInput.x) * speed * dt
        let tryPos = pos + delta
        if world.heightAt(x: Double(tryPos.x), z: Double(tryPos.y))
             >= world.config.seaLevel {
            pos = tryPos
        }
        // Eye: sample HERE and AHEAD — hills ahead are higher than your feet.
        let groundY = world.worldY(forHeight:
            world.heightAt(x: Double(pos.x), z: Double(pos.y)))
        let ahead = pos + forward * 8
        let aheadY = world.worldY(forHeight:
            world.heightAt(x: Double(ahead.x), z: Double(ahead.y)))
        let eye = SIMD3<Float>(pos.x, max(groundY, aheadY) + eyeHeight, pos.y)
        let cp = cos(pitch)
        let look = eye + SIMD3<Float>(sin(yaw) * cp, sin(pitch),
                                      cos(yaw) * cp) * 10
        let aspect = Float(view.bounds.width / max(1, view.bounds.height))
        view.setCamera(position: eye, target: look, aspect: aspect)
    }
}

The ahead-sample is not optional. Sampling only at the player's feet puts the camera inside uphill terrain — the classic "camera glitches under the map when walking up hills" bug. Eight units ahead at 45 u/s gives ~0.18 s of lookahead: enough to ride up slopes smoothly without floating.

Frame-rate-independent movement

  • Use the dt from onFrame (TimeInterval). Clamp it: let dt = min(frameDt, 0.1) — a backgrounded app returning with dt = 30 shouldn't teleport the player.
  • Throttle interactive controls during the interaction. Sun sliders and noise sliders must update uniforms per frame (cheap) without triggering rebuilds (expensive). Coalesce: apply the value continuously, apply the consequences on release.
  • Keep onFrame to camera math + input integration. Game logic, networking, and UI sync belong on the main thread.

Collision with terrain (beyond walking)

The library gives you one collision primitive — the heightfield — and it's enough for most gameplay:

// Keep any object above ground:
func groundClamp(_ p: inout SIMD3<Float>, world: MTTerrainWorld,
                 clearance: Float) {
    let h = world.heightAt(x: Double(p.x), z: Double(p.z))
    p.y = max(p.y, world.worldY(forHeight: h) + clearance)
}

// Raycast-ish: march a ray until it goes under the terrain (for tap-to-move):
func pickGround(from eye: SIMD3<Float>, dir: SIMD3<Float>,
                world: MTTerrainWorld) -> SIMD3<Float>? {
    var t: Float = 0
    for _ in 0..<200 {
        let p = eye + dir * t
        let h = world.heightAt(x: Double(p.x), z: Double(p.z))
        if p.y <= world.worldY(forHeight: h) { return p }
        t += max(2, (p.y - world.worldY(forHeight: h)) * 0.5)
    }
    return nil
}
