Architecture

How MetalTerrain fits together: the module layout, the data flow from seed to pixels, the threading model, and why the library/app split exists.

Module map

MetalTerrain/
├── Core/                      pure Swift, no Metal, no I/O
│   ├── MTTerrainWorld.swift   the world: seed + config → heights, biomes, structures
│   ├── MTConfig.swift         MTTerrainConfig — every tweakable, clamped
│   ├── MTChunk.swift          MTChunkCoord + MTChunk (heightmap grid)
│   ├── MTBiome.swift          MTBiome — height bands with coloring rules
│   └── MTCapabilities.swift   GPU feature queries (ray tracing, mesh shading)
├── Noise/                     pure Swift, deterministic
│   ├── MTNoise.swift          MTNoiseConfig + the layered height pipeline
│   ├── MTPerlinNoise.swift    seeded 2D gradient noise
│   └── MTSeededRandom.swift   xorshift64* PRNG — the only "randomness" anywhere
├── Rendering/                 Swift + Metal
│   ├── MTTerrainView.swift    MTKView subclass — the zero-boilerplate entry point
│   ├── MTTerrainRenderer.swift chunk streaming, LOD, draw submission
│   ├── MTMeshBuilder.swift    height grids → indexed triangle meshes
│   ├── MTRayTracing.swift     BLAS/TLAS for hardware sun shadows (M3_FEATURES)
│   └── MTSkybox.swift         procedural sky + sun disc
└── Structures/                pure Swift geometry
    └── MTStructures.swift     7 procedural structure meshes + placement types

The dependency arrows point one way: Rendering → Core/Noise, and Structures is standalone geometry. Nothing in Core or Noise imports Metal — you can unit-test world generation on any platform, including Linux.

Data flow: seed to pixels

 (1) SAMPLE          (2) MESH           (3) STREAM          (4) SHADE
 seed,config ─▶ heights ─▶ vertices ─▶ GPU buffers ─▶ pixels
    │               │            │              │             │
 MTTerrainWorld  MTMeshBuilder  background    MTTerrainRenderer  Metal shaders
 heightAt()      buildTerrain-  queue         update() → draw()
 generateChunk() Mesh()         (nearest-     1 draw/chunk
                 normals via     first)       + water + sky
                 central diffs   LRU cache
                 skirts
  1. Sample. height(x:y:config:) runs the layered noise pipeline (continent → warp → detail → mountains → rivers → coastal shelf) and returns a normalized height in 0…1. generateChunk(at:) samples a full grid. Pure function of (seed, config).
  2. Mesh. The grid becomes indexed triangles: positions from worldY(forHeight:), normals from central differences of the heightfield (border vertices sample the true neighbor via world.heightAt so adjacent chunks compute identical edge normals), colors from biome lookup with border blending and slope-based cliffs. Vertical skirts hang off every border so the world reads as a solid block.
  3. Stream. update(cameraTarget:) computes the needed chunk square, evicts out-of-range chunks (keeping a one-chunk safety ring briefly), and dispatches missing builds nearest-first to a background queue. Finished meshes are installed under a lock; draw never blocks on a build.
  4. Shade. Per frame: skybox first (fullscreen triangle, no depth write), then frustum-culled chunks (one draw each), structures (one instanced draw per kind), water (blended, last). The fragment shader does biome lighting, per-pixel bump, specular/fresnel (if enabled), analytic shadows (+ ray-traced on M3 builds), fog, and the optional wireframe overlay.

Threading model

WhatWhereNotes
Chunk mesh buildingcom.MetalTerrain.meshBuild (.userInitiated, concurrent) Builds are stamped with buildGeneration; stale ones self-drop.
Structure placement queriesSame build queue world.structures(in:) per visible chunk.
Instance buffer swapMain queuePlacement on build queue, swap on main.
Chunk cacheGuarded by NSLock (cacheLock) Read by draw, written by build completions.
update / drawRender thread (via onFrame) draw never waits for builds.
Uniform buffersTriple-buffered + semaphore(3) CPU never overwrites a slot the GPU is reading.
TLAS refresh (M3)Render thread, throttled to every 15 frames Skipped when the chunk set is unchanged.

The one rule: draw only ever renders finished meshes. The visible set grows/shrinks by completed builds — there is no code path where the render thread waits on generation. That's what keeps the frame rate smooth while the world streams in around you.

Why the library owns all the Metal

The founding rule (from the project's first week): the library owns pipelines, shaders, LOD, streaming, and Metal state; the app owns camera, input, and UI. Consequences:

  • Apps can't break rendering by misconfiguring Metal state — there is no Metal state for apps to configure.
  • Bug fixes to streaming or shading land in one place and benefit every app.
  • The overlay closure on draw(in:overlay:) is the only sanctioned way for apps to inject custom drawing — inside the library's render pass, with the library's encoder state managed around it.
  • Camera control stays in the app because feel is app-specific (orbit vs. walk vs. cinematic rails), while rendering is not.

Key invariants (for contributors)

  • Determinism: same (seed, config) → same heights, biomes, chunks, structures, on every device, every run.
  • No I/O in generation: no files, no network, no SystemRandomNumberGenerator, no Date in the noise path.
  • Vertex layout: MTVertex is 3× SIMD4 (48 bytes) — never SIMD3, because Swift pads it to 16 bytes while Metal packs float3 as 12.
  • Winding: counter-clockwise seen from outside (from +Y for terrain). The terrain comment "was clockwise → terrain invisible from above" is preserved as a warning.
  • Water is flat. Geometric displacement never touches water vertices; water animation is fragment-shader only. (A hard requirement from real usage: waves must not move the shoreline.)
  • Leak review: every closure/async addition gets reviewed for retain cycles and buffer/cache leaks — a standing project rule.
