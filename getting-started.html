Getting Started

Get a live 3D terrain rendering in about five minutes. This guide assumes an existing iOS app target in Xcode 16+ and a view where you can put an MTKView.

1. Add the package (1 minute)

MetalTerrain is a plain Swift package — no dependencies.

In Xcode:

  1. File → Add Package Dependencies…
  2. Enter the repository URL (https://github.com/a-user-of-python/MetalTerrain).
  3. Add MetalTerrain to your app target.

In Package.swift (if your app is itself a package):

dependencies: [
    .package(url: "https://github.com/a-user-of-python/MetalTerrain", from: "1.1.0"),
],
targets: [
    .target(name: "YourApp", dependencies: ["MetalTerrain"]),
]

No extra setup, no plist keys, no capabilities to enable.

2. Five lines to your first terrain (2 minutes)

MTTerrainView is a drop-in MTKView subclass — no MetalKit boilerplate needed:

import MetalTerrain

let terrainView = MTTerrainView(frame: view.bounds)
terrainView.world = MTTerrainWorld(seed: 1337)
view.addSubview(terrainView)

terrainView.onFrame = { tv, dt in
    tv.setCamera(position: [0, 220, 320], target: [0, 0, 0], aspect: aspect)
}

That's it. The library handles the device, pixel formats, render loop, chunk streaming, LOD, and shaders. You only write camera logic.

Manual setup with MTTerrainRenderer

If you need your own MTKView (custom delegate, shared device), use MTTerrainRenderer directly:

import MetalTerrain
import MetalKit

final class TerrainScene {
    let device: MTLDevice
    let world: MTTerrainWorld
    let renderer: MTTerrainRenderer

    init(view: MTKView) {
        device = MTLCreateSystemDefaultDevice()!
        view.device = device
        view.colorPixelFormat = .bgra8Unorm
        view.depthStencilPixelFormat = .depth32Float

        world = MTTerrainWorld(seed: 1337)
        renderer = MTTerrainRenderer(device: device, world: world)

        renderer.setCamera(position: [0, 220, 320], target: [0, 0, 0],
                           fovDegrees: 60, aspect: Float(view.bounds.width / view.bounds.height),
                           near: 0.1, far: 6000)
    }

    func frame(view: MTKView) {
        renderer.update(cameraTarget: SIMD2(0, 0))  // streams chunks around this point
        renderer.draw(in: view)
    }
}

Wire frame(view:) into MTKViewDelegate.draw(in:). SwiftUI note: wrap MTKView in a UIViewRepresentable, create one scene in the coordinator, and call frame(view:) from the delegate.

3. Camera setup (1 minute)

setCamera(position:target:fovDegrees:aspect:near:far:) is the only camera API:

ParameterWhat it doesStarting value
positionWhere the camera sits (world units)[0, 220, 320] — high and back
targetWhat it looks at[0, 0, 0] — the world origin
fovDegreesField of view60 — natural perspective
aspectWidth ÷ height of the viewFrom view.bounds
nearNearest visible distance0.1
farFarthest visible distance6000

Three rules that save you debugging time:

  1. Update aspect on rotation/resize or the terrain will stretch.
  2. far must cover the visible world. Default chunks reach ~768 units; 6000 is safe.
  3. Keep the camera above the terrain. Use world.heightAt(x:z:) + world.worldY(forHeight:) to clamp: camera.y = max(camera.y, groundY + 5).

update(cameraTarget:) streams chunks around the camera target each frame — pass the XZ your camera is looking at and the world pages itself in.

4. Common first tweaks

// A different world: just change the seed
world = MTTerrainWorld(seed: 424242)

// More (or fewer) chunks visible — bigger number, farther horizon
var config = MTTerrainConfig.default
config.viewDistance = 8
world.config = config

// Turn off structures for a clean landscape study
world.structuresEnabled = false

// Debug the mesh itself
renderer.wireframe = true

// Hide the water plane
renderer.showsWater = false

// Islands everywhere: raise the sea level
var islandConfig = MTTerrainConfig.default
islandConfig.seaLevel = 0.58
world.config = islandConfig

// Find a safe spawn point (land, above sea, below mountains)
let spawn: SIMD2<Float> = world.findSafeSpawn()

Troubleshooting

  • Black screen: check view.device is set, colorPixelFormat is .bgra8Unorm, and far is large enough. Try renderer.wireframe = true.
  • Everything is water (or nothing is): seaLevel is wrong for the noise config — defaults are tuned to each other. See Noise Tuning.
  • Stretched image after rotation: update aspect in setCamera.
  • Low frame rate: see Performance — start with a smaller viewDistance.

3. SwiftUI integration

MTTerrainView is a UIView (MTKView subclass), so wrap it with UIViewRepresentable:

import SwiftUI
import MetalTerrain

struct TerrainViewWrapper: UIViewRepresentable {
    let world: MTTerrainWorld

    func makeUIView(context: Context) -> MTTerrainView {
        let tv = MTTerrainView(frame: .zero)
        tv.world = world
        // Drive the camera every frame. Keep this closure cheap:
        // it runs on the render thread.
        tv.onFrame = { view, dt in
            context.coordinator.updateCamera(view: view, dt: dt)
        }
        return tv
    }

    func updateUIView(_ uiView: MTTerrainView, context: Context) {
        // Push SwiftUI state (sliders, toggles) into the renderer here.
        uiView.renderer?.sunElevation = context.coordinator.sunElevation
    }

    func makeCoordinator() -> Coordinator { Coordinator() }

    class Coordinator {
        var yaw: Float = 0, pitch: Float = -0.5, distance: Float = 900
        var sunElevation: Float = 0.6
        var target = SIMD3<Float>(0, 0, 0)

        func updateCamera(view: MTTerrainView, dt: TimeInterval) {
            yaw += Float(dt) * 0.1  // slow auto-orbit; replace with your input
            let eye = SIMD3<Float>(
                target.x + distance * cos(pitch) * sin(yaw),
                target.y + distance * sin(pitch),
                target.z + distance * cos(pitch) * cos(yaw))
            let aspect = Float(view.bounds.width / max(1, view.bounds.height))
            view.setCamera(position: eye, target: target, aspect: aspect)
        }
    }
}

Threading rule: onFrame runs on the render thread, not the main thread. It is safe to call setCamera and read view.renderer there. Do not touch UIKit/SwiftUI state from inside it — copy values into your coordinator on the main thread and read them in onFrame.

4. Your first camera rig: orbit + walk

Two camera modes cover 90% of apps. The library never moves the camera for you — these snippets are the standard patterns:

// ORBIT (third-person / map view)
func orbitCamera(view: MTTerrainView, target: SIMD3<Float>,
                 yaw: Float, pitch: Float, distance: Float) {
    let eye = SIMD3<Float>(
        target.x + distance * cos(pitch) * sin(yaw),
        max(10, target.y + distance * sin(pitch)),  // never below ground plane
        target.z + distance * cos(pitch) * cos(yaw))
    let aspect = Float(view.bounds.width / max(1, view.bounds.height))
    view.setCamera(position: eye, target: target, aspect: aspect)
}

// WALK (first-person). Sample the terrain so the eye stays above ground.
func walkCamera(view: MTTerrainView, world: MTTerrainWorld,
                pos: SIMD2<Float>, yaw: Float, eyeHeight: Float = 2) {
    let groundY = world.worldY(forHeight: world.heightAt(x: Double(pos.x),
                                                         z: Double(pos.y)))
    // Look ahead: keeps the camera out of uphill terrain.
    let ahead = pos + SIMD2<Float>(sin(yaw), cos(yaw)) * 8
    let aheadY = world.worldY(forHeight: world.heightAt(x: Double(ahead.x),
                                                        z: Double(ahead.y)))
    let eye = SIMD3<Float>(pos.x, max(groundY, aheadY) + eyeHeight, pos.y)
    let look = eye + SIMD3<Float>(sin(yaw), -0.1, cos(yaw)) * 10
    let aspect = Float(view.bounds.width / max(1, view.bounds.height))
    view.setCamera(position: eye, target: look, aspect: aspect)
}

See Camera & Input for the full guide: smoothing, collision with terrain, water blocking, and frame-rate-independent movement.

5. Choosing a spawn point

Don't spawn at the origin blindly — it might be ocean. Use the built-in search:

let world = MTTerrainWorld(seed: 1337)
let spawn = world.findSafeSpawn()   // SIMD2<Float>: land above sea level, below mountains
// Falls back to (0, 0) on pathological ocean-heavy seeds — check the height:
let h = world.heightAt(x: Double(spawn.x), z: Double(spawn.y))
assert(h > world.config.seaLevel, "spawn is underwater; pick another seed")

findSafeSpawn() spiral-searches outward from the origin and returns the first point that is safely above sea level but not in the high mountains. It's deterministic per seed.

Common mistakes

MistakeSymptomFix
Never calling setCameraBlack screen, but FPS counter runs Drive the camera every frame from onFrame.
Camera below the terrainBlack screen or inside-the-mountain view Sample world.heightAt and keep the eye above it (see walk snippet).
Changing config every frameConstant re-generation, low FPS Batch config changes; the world bumps configVersion and rebuilds on each set.
Reading world.seed to "randomize"Same world every launch That's the point — store a user-chosen seed, e.g. UInt64.random(in: 1...999_999) once.
Forgetting aspectStretched terrain Pass the real view aspect every frame; update on rotation.
Heavy work in onFrameFrame hitches Keep it to camera math. Do game logic on the main thread.

Troubleshooting

The view is black but the app runs

  • Is world assigned? MTTerrainView with a nil world renders nothing.
  • Is setCamera being called? Add a breakpoint or print in onFrame.
  • Is the camera under the terrain? Print the eye Y vs worldY(forHeight: heightAt).
  • Check the Xcode console for Metal validation errors (enable Metal API Validation in the scheme).

Terrain appears but is flat gray

Biome lookup may be failing — verify config.biomes is non-empty, or call world.resetBiomesToDefault(). A custom biome with an inverted minHeight > maxHeight band matches nothing.

It works in the simulator but is slow

Expected. The iOS Simulator has no GPU — Metal runs on the CPU. Always judge performance on a physical device. (The simulator is still fine for layout and logic.)

Build error: "no such module 'MetalTerrain'"

The package wasn't added to the app target. In Xcode: select the app target → General → Frameworks, Libraries, and Embedded Content → confirm MetalTerrain is listed. If your app is itself a Swift package, check the dependencies array in Package.swift.
