Chunk Streaming & LOD

How the infinite world pages in around the camera: the chunk lifecycle, the background build queue, eviction policy, LOD, and the anti-hole guarantees.

The chunk lifecycle

needed = square(viewDistance) around camera
    │
    ├─▶ in cache ─▶ frustum test ─▶ draw (1 draw call)
    │
    ├─▶ missing ─▶ dispatch to build queue (nearest-first)
    │                  │
    │                  ├─▶ generation changed while queued? → drop (no work done)
    │                  ├─▶ generate heights → build mesh → create MTLBuffers
    │                  └─▶ generation changed while building? → drop (no install)
    │                  └─▶ install into cache under lock
    │
    └─▶ out of range ─▶ evict (Chebyshev distance > radius + 1)
                        └─▶ safety ring: +1 ring kept briefly while replacements build

update(cameraTarget:) in detail

Called every frame with the camera target's world XZ. Steps:

  1. Config check. If world.configVersion changed, invalidate caches and rebuild the water plane. (This is why setting config is not free — batch your changes.)
  2. Fast path. If the camera hasn't crossed a chunk boundary since last frame, almost nothing happens — the needed set is identical.
  3. Needed set. The square of chunk coords within radius = viewDistance of the camera chunk.
  4. Eviction. Cached chunks with Chebyshev distance > radius + 1 are evicted. The +1 is the safety ring: chunks just outside the view radius are retained while their replacements build, so fast movement never reveals holes where chunks should connect.
  5. Dispatch. Missing chunks are sorted nearest-first and dispatched to the concurrent build queue (com.MetalTerrain.meshBuild, .userInitiated).
  6. Cache cap. LRU cap at min((2×(radius+1)+1)², 300) chunks — sized to hold the view square plus the safety ring.

The build queue and buildGeneration

Every config change (including seed changes and the Regenerate button) bumps a buildGeneration counter. Each dispatched build captures the generation at dispatch time and checks it twice:

  • Before expensive work: if a newer generation was requested while this build sat queued, it's dropped without sampling a single noise value.
  • After building: if the generation changed mid-build, the finished mesh is discarded instead of installed.

This is what makes rapid Regenerate taps safe: at most one generation's worth of builds ever does real work. (The 1.5 s UI debounce is the second layer.)

LOD (level of detail)

Chunks far from the camera don't need full vertex density. The design:

  • distanceFactor = dist / (viewDistance × chunkWorldSize), 0 at the camera, 1 at the view edge.
  • Chunks with distanceFactor > 0.4 generate at resolutionScale: 0.5 — half the vertices per side, 4× fewer noise evaluations and 4× fewer triangles.
  • MTMeshBuilder.buildLOD(for:world:distanceFactor:) selects the mesh stride from the same factor.

Current status: LOD is temporarily disabled (all chunks build at full resolution) because mixed-resolution neighbors produced T-junction cracks — vertices of a full-res chunk that don't lie on the half-res neighbor's edge. Border normals already sample true neighbor heights (no lighting seams); proper border stitching will re-enable LOD without cracks. The 5× chunk-build speedup keeps full-res streaming smooth in the meantime.

Anti-hole guarantees

Three mechanisms, layered:

  1. Skirts. Every chunk mesh gets vertical skirts on all four borders (depth heightScale × 0.35 + 10). Even if two neighbors disagree slightly, you see skirt wall, not sky.
  2. Safety ring. Eviction keeps radius + 1, so a chunk is never removed before its replacement exists.
  3. Border normals. Edge-vertex normals are computed from true neighbor heights via world.heightAt, so adjacent chunks shade identically at the seam — no lighting discontinuity even where geometry meets.

Frustum culling

Each cached chunk stores an AABB (XZ extent from its coord, Y from min/max height ± 20). Every frame the renderer extracts the frustum planes from the view-projection matrix and skips chunks entirely outside it — no draw call, no vertex processing. Chunks behind the camera or beyond the far plane cost essentially nothing.

Tuning streaming

// Bigger view, more streaming work (quadratic!):
view.viewDistance = 8   // → world.config.viewDistance; rebuilds the stream

// Smaller chunks stream faster but show more pop-in at the horizon:
var config = MTTerrainConfig.default
config.chunkResolution = 192   // fewer verts → faster builds
config.chunkWorldSize = 1000   // keep world scale constant
world.config = config
  • Pop-in at the horizon → raise viewDistance (costly) or accept it; nearest-first ordering means the area around you always resolves first.
  • Hitches while moving fast → the build queue is saturated. Lower chunkResolution or viewDistance. Check that you're not changing config per frame (each set invalidates everything).
  • Holes during fast movement → should not happen with the safety ring; if you see them, it's a bug — report the seed and camera path.
