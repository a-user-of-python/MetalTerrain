Performance Guide

MetalTerrain targets 60 fps on Apple Silicon. The math to budget chunks, what LOD buys you, memory estimates, and per-device settings.

All numbers use defaults (chunkResolution 64, chunkWorldSize 128, viewDistance 6).

Chunk budget math

viewDistance is a chunk radius. Live chunks = (2 × viewDistance + 1)².

viewDistanceChunksHorizon
481~512 units
6 (default)169~768 units
8289~1024 units
10441~1280 units

Each full-res chunk = 64×64 grid → 7,938 triangles. At viewDistance 6 that's ~1.34M tris worst case — before LOD. Triangle count scales with the square of viewDistance.

The two dials: viewDistance controls how much world is visible (cost ∝ square — turn down first). chunkResolution controls detail per chunk (turn down second).

LOD behavior

Chunks beyond viewDistance / 2 build at half resolution automatically — ¼ the vertices, ¼ the triangles. At viewDistance 6:

BandChunksTris/chunkTotal
Near (≤ 3)497,938~389K
Far (> 3)120~1,985~238K
Total169—~627K

LOD cuts the worst case roughly in half. Tune fog so the LOD boundary sits inside the haze.

Instancing (structures)

One low-poly mesh per kind (7 kinds), one instanced draw call per kind — a hundred trees = one draw call. structureDensity affects instance count, not draw calls.

Memory estimates

Per full-res chunk (64×64): vertices ~144 KB + indices ~95 KB + CPU heightmap ~16 KB ≈ ~255 KB. Per half-res chunk: ≈ ~64 KB.

Steady state at viewDistance 6 (49 full + 120 half): ~20 MB total.

  • Doubling viewDistance ≈ 4× memory.
  • Doubling chunkResolution ≈ 4× per-chunk memory.
  • Shared vertex format: position (float3) + normal (float3) + color (float3) = 36 bytes/vertex.
  • Chunk pooling: out-of-range chunks return buffers to a pool — steady-state movement allocates ~zero new GPU buffers.

If frames drop, in order: (1) lower viewDistance by 1–2, (2) lower chunkResolution to 48, (3) lower octaves to 4, (4) disable structures to isolate the cost.

Fill-rate check: renderer.wireframe = true — if wireframe runs dramatically faster, you're fragment-bound (overdraw, water transparency). Reduce overdraw, not chunks.

Profiling

Xcode 16 + Instruments → Metal System Trace, on a physical device (the Simulator tells you nothing useful about GPU performance):

  • Frame time: 16.7 ms budget. Consistent misses = structural (too many chunks); spikes = generation hitches.
  • Vertex vs. fragment: vertex-heavy → reduce resolution/distance; fragment-heavy → check water overdraw and fog.
  • Generation hitches: chunk generation runs on CPU during update — profile Time Profiler at generateChunk / mesh building.

Checklist before shipping

  • Profiled on the lowest device you support, not just the newest.
  • far plane ≥ viewDistance × chunkWorldSize.
  • Fog tuned so the LOD boundary sits in haze.
  • aspect updated on rotation.
  • Seed + config versioned together if persisted/shared.
