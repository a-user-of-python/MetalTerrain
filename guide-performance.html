Performance Guide

MetalTerrain targets 60 fps on Apple Silicon. The math to budget chunks, what LOD buys you, memory estimates, and per-device settings.

All numbers use defaults (chunkResolution 64, chunkWorldSize 128, viewDistance 6).

Chunk budget math

viewDistance is a chunk radius. Live chunks = (2 × viewDistance + 1)².

viewDistanceChunksHorizon
481~512 units
6 (default)169~768 units
8289~1024 units
10441~1280 units

Each full-res chunk = 64×64 grid → 7,938 triangles. At viewDistance 6 that's ~1.34M tris worst case — before LOD. Triangle count scales with the square of viewDistance.

The two dials: viewDistance controls how much world is visible (cost ∝ square — turn down first). chunkResolution controls detail per chunk (turn down second).

LOD behavior

Chunks beyond viewDistance / 2 build at half resolution automatically — ¼ the vertices, ¼ the triangles. At viewDistance 6:

BandChunksTris/chunkTotal
Near (≤ 3)497,938~389K
Far (> 3)120~1,985~238K
Total169—~627K

LOD cuts the worst case roughly in half. Tune fog so the LOD boundary sits inside the haze.

Instancing (structures)

One low-poly mesh per kind (7 kinds), one instanced draw call per kind — a hundred trees = one draw call. structureDensity affects instance count, not draw calls.

Memory estimates

Per full-res chunk (64×64): vertices ~144 KB + indices ~95 KB + CPU heightmap ~16 KB ≈ ~255 KB. Per half-res chunk: ≈ ~64 KB.

Steady state at viewDistance 6 (49 full + 120 half): ~20 MB total.

  • Doubling viewDistance ≈ 4× memory.
  • Doubling chunkResolution ≈ 4× per-chunk memory.
  • Shared vertex format: position (float3) + normal (float3) + color (float3) = 36 bytes/vertex.
  • Chunk pooling: out-of-range chunks return buffers to a pool — steady-state movement allocates ~zero new GPU buffers.

If frames drop, in order: (1) lower viewDistance by 1–2, (2) lower chunkResolution to 48, (3) lower octaves to 4, (4) disable structures to isolate the cost.

Fill-rate check: renderer.wireframe = true — if wireframe runs dramatically faster, you're fragment-bound (overdraw, water transparency). Reduce overdraw, not chunks.

Profiling

Xcode 16 + Instruments → Metal System Trace, on a physical device (the Simulator tells you nothing useful about GPU performance):

  • Frame time: 16.7 ms budget. Consistent misses = structural (too many chunks); spikes = generation hitches.
  • Vertex vs. fragment: vertex-heavy → reduce resolution/distance; fragment-heavy → check water overdraw and fog.
  • Generation hitches: chunk generation runs on CPU during update — profile Time Profiler at generateChunk / mesh building.

Checklist before shipping

  • Profiled on the lowest device you support, not just the newest.
  • far plane ≥ viewDistance × chunkWorldSize.
  • Fog tuned so the LOD boundary sits in haze.
  • aspect updated on rotation.
  • Seed + config versioned together if persisted/shared.

Defaults changed. The numbers below use the current defaults: chunkResolution 250, chunkWorldSize 1000, viewDistance 6, heightScale 400. Older versions of this page quoted 64/128 — those were stale.

Chunk budget math (corrected)

viewDistance is a chunk radius. Live chunks = (2 × viewDistance + 1)².

viewDistanceChunksHorizon
481~4,000 units

10 (max)441~10,000 units

Each full-resolution chunk is a 250×250 grid → 249 × 249 × 2 = 124,002 triangles. At viewDistance 6 that's ~21M triangles worst case — before frustum culling removes off-screen chunks and LOD halves distant ones. In practice the GPU sees a fraction of that, but the number explains why the two dials below matter.

The two dials

  • viewDistance — how much world is visible. Cost scales with the square. Turn this down first.
  • chunkResolution — detail per chunk. Turn down second. Halving resolution quarters the triangle count and quarters the noise evaluations per chunk build.

Where the frame time goes

StageThreadNotes
Chunk mesh building (noise → heights → mesh)Background queue Doesn't block rendering. Nearest-first ordering. ~2M noise evals per full-res chunk.
Buffer upload (CPU → GPU)Background queue MTLBuffer creation is thread-safe; done off the render thread.
Frustum culling + draw submissionRender thread One draw call per visible chunk; AABB-tested against the view frustum.
Vertex/fragment shadingGPU Per-pixel bump mapping and specular are the main fragment costs.
TLAS refresh (M3_FEATURES only)Render thread Throttled to every 15 frames; skipped when the chunk set is unchanged.

Memory estimates

Per chunk (full resolution, 250×250):

  • Heights: 62,500 × 4 bytes = 244 KB
  • Vertices: 62,500 × 48 bytes = 2.9 MB
  • Indices: 124,002 × 3 × 4 bytes ≈ 1.5 MB
  • Total ≈ 4.6 MB per chunk on the GPU.

At viewDistance 6 (169 chunks) that's ~780 MB worst case — but the LRU cache caps at min((2×(radius+1)+1)², 300) chunks, and frustum culling means most cached chunks aren't drawn. If memory pressure is a concern, lower viewDistance before anything else: it reduces chunk count quadratically.

LOD behavior

Chunks beyond 40% of the view distance generate at half resolution (resolutionScale: 0.5 → 4× fewer noise evaluations and 4× fewer triangles). MTMeshBuilder.buildLOD(for:world:distanceFactor:) selects the stride; distanceFactor is dist / (viewDistance × chunkWorldSize).

Current status: LOD is temporarily disabled (all chunks build at full resolution) while border stitching is implemented, to avoid T-junction cracks between LOD levels. The 5× chunk-build speedup keeps this fast enough on current hardware. This page will be updated when LOD returns.

Interactive controls must stay at 60 fps

A standing rule in this library's development: every interactive control gets throttled or coalesced and perf-checked during the interaction, not just at rest. If you expose sun sliders, noise sliders, or a regenerate button:

  • Debounce expensive actions. The Regenerate button uses a 1.5 s debounce; rapid taps don't queue hundreds of stale builds.
  • Generation-stamp queued work. Chunk builds capture a buildGeneration counter at dispatch; if the config changed while queued, the work is dropped before doing anything expensive.
  • Coalesce slider drags. A sun-angle slider should update uniforms every frame (cheap) but must not trigger pipeline recompiles or chunk rebuilds.
  • Profile while dragging. The sun-slider throttle was verified by watching FPS during adjustment ("never below 60 even when adjusting").

Profiling checklist

  1. Always profile on a physical device. Simulator numbers are meaningless.
  2. Use Xcode's Metal debugger (capture a frame) to see actual draw call counts and timings per encoder.
  3. Watch renderer.currentFPS / terrainView.fps — the exponential moving average smooths spikes; for hitch-hunting, instrument onFrame with your own min-frame-time tracker.
  4. Suspect chunk streaming if hitches correlate with movement; suspect the TLAS if they correlate with chunk-set changes on M3 builds; suspect fragment cost if FPS is uniformly low while stationary (try detailAmount = 0 as a bisect).
  5. Check thermal state — sustained 60 fps on a hot iPad throttles the GPU. That's the device protecting itself, not a bug.
