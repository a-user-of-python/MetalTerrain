Chip Support

Which Apple chips support the M3-family GPU features: hardware ray tracing and mesh shading.

The library never guesses from the device name — it queries device.supportsRayTracing and device.supportsFamily(.apple9) at runtime via MTCapabilities. This table is the human-readable version of those checks.

What "no" means in practice

On unsupported chips, everything still works: the same API, the same worlds, the same 60 fps target. The differences are:

  • Shadows: analytic shadow term instead of ray-traced — same sun, same direction, softer contact. Intentionally subtle.
  • Mesh generation: CPU MTMeshBuilder instead of GPU mesh shaders — identical visuals.
  • Skybox: works everywhere, including M1/M2.

An M3_FEATURES build still runs on M1/M2/A16 — the runtime checks fall back to the standard paths automatically. It just won't engage the hardware features.

Checking at runtime

import MetalTerrain

let rt = MTCapabilities.supportsHardwareRayTracing(device: device)
let mesh = MTCapabilities.supportsMeshShading(device: device)

if rt && mesh {
    // M3-family GPU: enable your M3-only UI, quality options, etc.
}

How to query at runtime

Both queries are pure — they never change device state — so call them once at startup and cache the result:

import MetalTerrain

let device = MTLCreateSystemDefaultDevice()!
let canRayTrace  = MTCapabilities.supportsHardwareRayTracing(device: device)
let canMeshShade = MTCapabilities.supportsMeshShading(device: device)

// Typical usage: gate an "Enhanced graphics" toggle
enhancedToggle.isHidden = !(canRayTrace || canMeshShade)

Two gates, not one. Hardware support (these queries) is necessary but not sufficient: the M3_FEATURES Swift/Metal build flag must also be set, or the ray-tracing and mesh-shading code paths aren't compiled in at all. Ship two binaries (standard + M3-enhanced) or one M3_FEATURES binary that gracefully degrades — the renderer falls back automatically either way.

What "unsupported" actually means

Nothing breaks. On an M1 iPad or an A16 iPhone, with or without the M3_FEATURES flag, you get:

  • The full terrain, water, skybox, structures, fog, and wireframe.
  • Analytic sun shadows (the standard shadow path — the ray-traced shadows are a subtle enhancement, not a replacement).
  • The standard vertex-shader mesh path (pixel-identical to the mesh-shader path).
  • Procedural 3D detail via the vertex shader (detailAmount works everywhere).

The M3 extras are strictly additive. Never gate gameplay on them.

Build configurations

The recommended shipping setup is two IPA/binary variants from one codebase:

  • Standard: no M3_FEATURES. Runs everywhere iOS 17+ runs. Smallest binary.
  • Enhanced: M3_FEATURES set for Swift and Metal. On M3+/A17 Pro+ hardware it lights up ray-traced shadows and mesh shading automatically; on older hardware it behaves exactly like the standard build.

Because the renderer probes capabilities at runtime, the enhanced binary is safe to install on old devices — it just won't use the extras. The only reason to ship the standard binary is size, or caution.
