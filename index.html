MetalTerrain

A 3D terrain generation library for iOS — Swift + native Metal. Seeded infinite worlds with mountains, oceans, forests, and villages, rendered at 60 fps.

Design principle: the library owns everything Metal — LOD, shaders, pipelines, chunk streaming, instancing. Your app only handles what it must: the view hierarchy, camera, input, and UI.

The 30-second pitch

Add one Swift package, write five lines, and your app has an endless explorable 3D world: mountains, beaches, oceans, forests, snowy peaks, plus scattered low-poly structures — all deterministic from a single seed. Change the seed and get a brand-new planet. No assets, no textures, no physics engine, no third-party code.

Quickstart — 5 lines

import MetalTerrain

let terrainView = MTTerrainView(frame: view.bounds)
terrainView.world = MTTerrainWorld(seed: 1337)
view.addSubview(terrainView)

terrainView.onFrame = { tv, dt in
    // Your camera logic here — the library handles the rest.
    tv.setCamera(position: eye, target: lookAt, aspect: aspect)
}

For full control (custom MTKView, manual render loop), use MTTerrainRenderer directly. See Getting Started.

Features

🌍 Seeded infinite terrain

Deterministic heightmap — the same seed always builds the same world, on any device.

🧩 Chunked streaming

The world pages in around the camera; unused chunks are pooled and reused.

🎨 Data-driven biomes

7 built-ins keyed on height; add or override your own at runtime.

🔊 Exposed noise config

Seed, octaves, frequency, lacunarity, gain, domain warp, ridged mountain mode.

🏘️ Seeded structures

Houses, towers, trees, boulders, wells, windmills, dungeons — one instanced draw call per kind.

⚡ Metal renderer

Metal 4 fast paths where available, Metal 3 fallback. LOD handled internally.

☀️ Skybox + sun

Gradient sky with a visible sun disc that follows your sun angle.

✨ M3+ extras

Hardware ray-traced shadows and mesh shading on M3/M4/M5 and A17 Pro+.

📦 Zero assets

Vertex colors only — no textures, no downloads.

How it works (the 60-second version)

A MetalTerrain world is a pure function of a seed. There is no stored map, no downloaded asset, no server. Given the same seed and config, every device computes the exact same mountains, rivers, and villages — down to the placement of every tree. This is what makes the worlds "infinite": the library only ever generates the small patch of world around the camera, and it can regenerate any patch identically on demand.

seed (UInt64)
  └─▶ noise field ─┬─▶ heightmap (continents, mountains, rivers, beaches)
                   ├─▶ biome lookup (height → color/material)
                   └─▶ structure placement (seeded PRNG per chunk)
  └─▶ chunk streaming ─▶ GPU meshes ─▶ Metal renderer ─▶ your screen

The pipeline has four stages, and the library owns all of them:

  1. Sampling (MTTerrainWorld): layered Perlin noise is combined into a normalized height in 0…1. Domain warping bends the noise so coastlines and rivers look natural instead of blobby.
  2. Meshing (MTMeshBuilder): each chunk's height grid becomes triangles with computed normals and per-vertex biome colors. Border vertices get small vertical skirts so neighboring chunks never show gaps.
  3. Streaming (MTTerrainRenderer): chunks are built on a background queue, nearest-first, and uploaded to GPU buffers. Chunks outside the view radius are evicted; a one-chunk safety ring is kept briefly so fast movement never reveals holes.
  4. Shading (Metal shaders): per-biome lighting, procedural detail, analytic + optional ray-traced shadows, fog, water, and sky.

Determinism is a feature, not an accident. heightAt(x:z:), generateChunk(at:), structures(in:), and biomeAt(height:) are all pure functions of (seed, config). This means minimaps, spawn logic, save files, and multiplayer reconciliation can all rely on the world being identical everywhere. See Architecture for the full picture.

Who MetalTerrain is for

  • Game prototypes — drop in an explorable 3D world in an afternoon; spend your time on gameplay, not terrain tooling.
  • Tech demos & benchmarks — a demanding but well-behaved Metal workload with a built-in FPS readout.
  • Education — a complete, readable example of procedural generation, chunked LOD, and Metal rendering in Swift.
  • Ambient / toy apps — endless flyover screensavers, terrain wallpapers, world-explorer toys.

What MetalTerrain is not

  • Not a game engine — there is no physics, no character controller, no collision beyond the height query you call yourself (world.heightAt(x:z:)).
  • Not an editor — worlds are generated, not painted. You tune them with seeds, noise parameters, and biome bands.
  • Not cross-platform — Apple platforms only (iOS 17+, macOS 14+ for the curious; the library is iOS-first).

Library vs. app responsibilities

This split is the most important thing to understand before you write code:

Library owns (don't reimplement)App owns (your job)
Heightfield math, noise, biomesCamera: position, look direction, FOV
Chunk streaming, LOD, evictionInput: touch, joystick, gestures
Mesh building, normals, skirtsGameplay: player, physics, objectives
Pipelines, shaders, shadow mapsUI: HUD, menus, settings screens
Structure placement & instancingOverlays: custom draws via the overlay closure
Water plane, skybox, fogPersistence: which seed the player chose

If you find yourself writing Metal boilerplate, stop — the library probably already does it. If you find yourself fighting the library for camera control, you're holding it wrong: the library never moves the camera. See Camera & Input.
