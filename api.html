API Reference

Every public type in MetalTerrain. Conventions:

  • Deterministic — same inputs (seed + config) → same output, on every run and every device. All world generation is deterministic.
  • Heights are normalized 0…1 unless a function name says otherwise. worldY(forHeight:) converts to world-space Y.

MTTerrainView

public final class MTTerrainView: MTKView

The zero-boilerplate integration. Drop it in a view hierarchy, assign a world, and drive the camera from onFrame. Device creation, pixel formats, the render loop, FPS tracking, and chunk streaming are all internal.

public var world: MTTerrainWorld?
public private(set) var renderer: MTTerrainRenderer?
public private(set) var fps: Double
public var onFrame: ((MTTerrainView, TimeInterval) -> Void)?

public func setCamera(position: SIMD3<Float>, target: SIMD3<Float>,
                      fovDegrees: Float = 55, aspect: Float,
                      near: Float = 1, far: Float = 4000)

public var wireframe: Bool
public var showsWater: Bool
public var fogEnabled: Bool
public var shaderEffectsEnabled: Bool
public var sunAzimuth: Float
public var sunElevation: Float
public var viewDistance: Int
public var usesMetal4: Bool  // read-only
  • world — assigning a world creates the renderer (carrying over display settings). Assign nil to tear down.
  • onFrame — called every frame on the main thread after FPS tracking, before draw. Update your camera here via setCamera.
  • usesMetal4 — true when the Metal 4 pipeline compiled and is active.

MTTerrainRenderer

public final class MTTerrainRenderer

The Metal 3 renderer (with Metal 4 fast paths where available). Reference type — create once per MTLDevice. For custom MTKView setups; otherwise prefer MTTerrainView.

public init(device: MTLDevice, world: MTTerrainWorld)
public var world: MTTerrainWorld

public func setCamera(position: SIMD3<Float>, target: SIMD3<Float>,
                      fovDegrees: Float, aspect: Float,
                      near: Float, far: Float)

/// Call every frame. Handles chunk streaming around the camera target.
public func update(cameraTarget: SIMD2<Float>)
public func draw(in view: MTKView)

public var wireframe: Bool
public var showsWater: Bool
public var skybox: MTSkybox?
public var rayTracing: MTRayTracing?  // nil unless built with M3_FEATURES
  • init(device:world:) — compiles the shader library, creates pipeline state, sets up chunk and structure buffers.
  • world — swap the world to render a different planet (meshes rebuild on next update).
  • setCamera(...) — re-call on resize to update aspect. far must exceed viewDistance × chunkWorldSize.
  • update(cameraTarget:) — streams chunks around the camera target: generates missing chunks, builds GPU buffers, recycles out-of-range ones. Bounded per-frame work — fast camera moves cause gradual pop-in, not hitches.
  • draw(in:) — encodes one frame: skybox, terrain chunks (front-to-back), water plane, then one instanced draw per structure kind.
  • wireframe — triangle edges instead of filled faces (debugging).
  • showsWater — translucent water plane at sea level (default true).
  • skybox — created by default, drawn first each frame. Set to nil to disable. See Skybox.
  • rayTracing — non-nil only when built with M3_FEATURES and the device supports it. Driven automatically. See Ray Tracing.

Threading: update and draw are not thread-safe with each other — call both from the same thread (normally main via MTKViewDelegate). MTTerrainWorld query methods are safe from background threads.

MTTerrainWorld

public final class MTTerrainWorld

The main entry point. Reference type — share one instance between game logic and the renderer.

/// Land above sea level, below the mountains. (0,0) if none found.
public func findSafeSpawn() -> SIMD2<Float>

public func biomeAt(height: Float) -> MTBiome

/// Generate a chunk's heightmap. Deterministic.
public func generateChunk(at coord: MTChunkCoord) -> MTChunk

/// Structures toggle (live).
public var structuresEnabled: Bool

/// Structure placements intersecting a chunk. Deterministic.
public func structures(in coord: MTChunkCoord) -> [MTStructurePlacement]

public func setBiome(_ biome: MTBiome)
public func removeBiome(named name: String)
public func resetBiomesToDefault()

public func worldY(forHeight h: Float) -> Float
  • init(seed:config:) — seed is the world's identity. Same seed + same config = same planet, on any device.
  • heightAt(x:z:) — the core query. Pure function of the seed: gameplay code and rendered meshes can never disagree.
  • findSafeSpawn() — spiral-searches for land above sea level and below mountains. Ideal player spawn.
  • biomeAt(height:) — custom biomes checked first (insertion order), then built-ins.
  • structures(in:) — deterministic placements per chunk.
  • setBiome / removeBiome / resetBiomesToDefault — runtime biome editing. setBiome with an existing name replaces in place.
let h: Float = world.heightAt(x: 1234.5, z: -987.0)
let groundY = world.worldY(forHeight: h)   // where to stand the player

MTBiome

public struct MTBiome

One biome = one height band of the world, with its colors and behavior.

public struct MTBiome {
    public var name: String
    public var minHeight: Float   // normalized 0...1, inclusive
    public var maxHeight: Float   // normalized 0...1, exclusive
    public var groundColor: SIMD3<Float>  // linear RGB 0...1
    public var slopeColor: SIMD3<Float>?  // steep-slope override (cliffs)
    public var emitsLight: Bool           // e.g. lava biome

    public init(name: String, minHeight: Float, maxHeight: Float,
                groundColor: SIMD3<Float>, slopeColor: SIMD3<Float>? = nil,
                emitsLight: Bool = false)
}

extension MTBiome {
    /// deepOcean, ocean, beach, grass, forest, mountain, snowyPeak
    public static var `default`: [MTBiome] { ... }
}
  • name is the identity — setBiome matches by name; a custom biome with an existing name replaces it.
  • minHeight inclusive, maxHeight exclusive — adjacent biomes tile without gaps when contiguous.
  • Colors are linear RGB 0…1, baked into vertex colors at mesh build.
  • slopeColor — steep slopes render as cliffs in this color.
  • emitsLight — self-illuminated (lava-style glow), skips NdotL darkening.

Full table and recipes: Biome Authoring.

public func resetBiomesToDefault()            // clear customs

Determinism contract

heightAt, generateChunk, structures(in:), biomeAt, and findSafeSpawn() are pure functions of (seed, config). No I/O, no unseeded randomness. Noise permutation tables are cached per seed (built once per seed change).

Structure placement policy

12 PRNG candidates per chunk from a chunk-seeded PRNG. A candidate is kept when the structure-density noise exceeds a structureDensity-derived threshold and the terrain height is in [beachTop, 0.85]; the kind comes from a second noise field mapped over the 7 kinds; rotation and scale come from the PRNG. structuresEnabled == false returns [].

                             from cameraPosition: SIMD3<Float>,

// Synchronous — use sparingly (≤ once per frame), low-res texture (256x128).

Draw order (per frame)

  1. Skybox — fullscreen triangle at the far plane, no depth writes.
  2. Terrain chunks — frustum-culled, one draw call each, back-face culled.
  3. Structures — one instanced draw per kind, double-sided (no culling).
  4. Water — blended, drawn last, depth-tested but no depth write.
  5. overlay closure — your objects, same encoder, same pass.

Threading

  • Chunk mesh building: dedicated concurrent queue (com.MetalTerrain.meshBuild, .userInitiated). Never blocks draw.
  • update(cameraTarget:) is throttled internally — cheap when the camera hasn't crossed a chunk boundary.
  • Structure instance buffers swap on the main queue; placement queries run on the build queue.
  • draw uses triple-buffered uniforms (semaphore of 3) — the CPU never overwrites a uniform slot the GPU is still reading.

MTVertex (mesh contract)

public struct MTVertex — the canonical terrain vertex. Three SIMD4<Float> (position, normal, color): 48 bytes. The w of color carries the material ID the shader uses for per-material effects: 0 = grass, 1 = rock, 2 = sand, 3 = snow, 4 = deep snow, 5 = water.

    public var normal: SIMD4<Float>
    public var color: SIMD4<Float>   // xyz = linear RGB, w = material ID
    public init(position: SIMD3<Float>, normal: SIMD3<Float>,
                color: SIMD3<Float>)
    public init(position: SIMD3<Float>, normal: SIMD3<Float>,
                color: SIMD4<Float>)
}

Why SIMD4 and not SIMD3? Swift pads SIMD3<Float> to 16 bytes but Metal packs float3 as 12 — a classic cross-language layout trap. Using SIMD4 everywhere removes all ambiguity between the Swift and Metal sides.
