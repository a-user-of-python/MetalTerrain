Advanced Features

The eye candy and power tools: smooth wireframe, procedural 3D detail, hardware ray tracing, mesh shading, skybox, and real-time reflections — what each one is, what it costs, and when to use it.

Smooth animated wireframe

Property: renderer.wireframe: Bool (default false) · terrainView.wireframe (forwarded)

Unlike traditional wireframe modes that draw raw triangle edges (the "Lego" look), MetalTerrain renders a smooth animated overlay in the fragment shader:

  • Contour lines — smooth iso-height bands that flow across the surface, following the actual geometry rather than the triangulation.
  • Grid overlay — a subtle world-aligned grid, anti-aliased with screen-space derivatives (fwidth) for crisp lines at any distance.
  • Animated pulse — a wave radiates from the camera, brightening lines as it passes: the "scanning" effect.
  • Distance fade — lines fade beyond ~800 units to prevent distant shimmer.

Implemented in both terrain_fragment and mesh_terrain_fragment, so it works on all devices with or without mesh shading.

renderer.wireframe = true   // the scan effect
terrainView.wireframe = true  // same, via the view

Use cases: debugging terrain generation (see the actual heightfield structure), visualizing LOD transitions, hologram/scan aesthetics.

Procedural 3D geometric detail

Property: renderer.detailAmount: Float (default 1.0, range 0…1)

Real geometric displacement — not coloring, not normal mapping. Vertices are physically moved along their normals by material-specific procedural noise, giving true 3D texture visible even at grazing angles:

MaterialEffectAmplitudeFrequency
Grass (0)Tufty bumps0.90.55
Rock (1)Craggy displacement1.60.35
Sand (2)Fine ripples0.351.4
Snow (3, 4)Soft drifts0.50.22
Water (5)None — stays flat0—

How it works: on the mesh-shader path (M3+), the mesh shader displaces vertices as it emits them with 2-octave value noise, perturbing normals by the noise gradient so lighting follows the bumps. On the standard path, the vertex shader applies the identical displacement — visual parity everywhere. The noise is a deterministic function of world position, so detail never swims or flickers as the camera moves.

Performance: per-vertex, not per-pixel — cheap. detailAmount = 0 disables it for maximum performance on older devices. Water never displaces — the plane must stay perfectly flat or the shoreline glitches.

renderer.detailAmount = 1.0  // full (default)
renderer.detailAmount = 0.5  // half
renderer.detailAmount = 0.0  // off — flat shading, fastest

Hardware ray tracing

Build flag: M3_FEATURES (Swift and Metal) · Runtime check: MTCapabilities.supportsHardwareRayTracing(device:)

One BLAS per terrain chunk (cached by chunk ID) plus one TLAS instancing every visible chunk. The terrain_fragment_rt pipeline traces sun rays against the TLAS at fragment buffer index 3. Subtle by design — it enhances the analytic shadows rather than replacing them. Falls back automatically without the flag or the hardware. No software fallback exists, deliberately.

Full details: Ray Tracing.

Mesh shading

Build flag: M3_FEATURES · Runtime check: MTCapabilities.supportsMeshShading(device:)

Terrain generated entirely on the GPU: the object shader culls per chunk and sizes the dispatch by LOD; the mesh shader emits one 8×8-quad tile per threadgroup; mesh_terrain_fragment is pixel-identical to the standard fragment shader. Falls back silently; the mesh pipeline compiles asynchronously so there's no startup hitch.

Full details: Mesh Shading.

// M3_FEATURES builds only:
terrainView.meshShadingEnabled = true   // default; false forces standard path

Skybox with visible sun

Property: renderer.skybox: MTSkybox? (created by default; set nil to disable)

One fullscreen triangle: gradient horizon→zenith, warm tint near the sun, visible sun disc, stars at night (negative elevation). The sun uses the same azimuth/elevation → direction mapping as the terrain lighting — disc and light always agree. The renderer mirrors sunAzimuth/sunElevation into the skybox automatically.

Full details: Skybox.

Real-time reflections

Method: renderer.renderReflection(to:from:lookingAt:fovDegrees:)

Renders skybox + terrain into an offscreen texture from an arbitrary camera — built for mirror reflections, available for any app-level effect:

// 256x128 is plenty for a mirror
let desc = MTLTextureDescriptor.texture2DDescriptor(
    pixelFormat: .bgra8Unorm, width: 256, height: 128, mipmapped: false)
desc.usage = [.renderTarget, .shaderRead]
desc.storageMode = .private
let reflectionTex = device.makeTexture(descriptor: desc)!

renderer.renderReflection(to: reflectionTex,
                          from: carPosition + SIMD3<Float>(0, 4, 0),
                          lookingAt: carPosition - forward * 50)
  • Structures and water are skipped in reflection passes (small in mirrors anyway).
  • Uses a dedicated uniform slot beyond the frame slots — main render state is undisturbed.
  • Synchronous (waitUntilCompleted) — call at most once per frame, with a small texture.

Shader effects (specular + fresnel)

Property: renderer.shaderEffectsEnabled: Bool (default false)

Per-material specular response: rock dull, sand matte, grass slight sheen, snow a soft glow, water mirror-like. Fresnel rim at grazing angles. Off by default — the base look is deliberately non-shiny; enable it when you want wet/glossy materials.

Putting it all together

import MetalTerrain

let renderer = MTTerrainRenderer(device: device, world: world)

// Eye candy (M3+ device + M3_FEATURES build for the RT/mesh-shader lines)
renderer.wireframe = false            // true for the scan effect
renderer.detailAmount = 1.0            // full procedural 3D detail
renderer.shaderEffectsEnabled = true   // specular + fresnel
// Ray-traced shadows + mesh shading engage automatically when available.

// Per frame
renderer.setCamera(position: camPos, target: camTarget,
                   fovDegrees: 55, aspect: aspect, near: 1, far: 4000)
renderer.update(cameraTarget: SIMD2<Float>(camTarget.x, camTarget.z))
renderer.draw(in: view)
